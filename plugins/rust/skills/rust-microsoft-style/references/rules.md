# Microsoft Pragmatic Rust Guidelines: condensed rules

Public Microsoft recommendations for Rust applications, libraries, macros, FFI, performance, and tooling. Conditional advice applies only in its stated context.

The source distinguishes requirements from recommendations. Preserve those distinctions when consulting the original; do not elevate every preference to a hard prohibition. Referenced but absent guideline IDs are not reconstructed here.

## Quick rules

Each source rule appears once below; read the sections relevant to the change.

“Recommended” marks the source’s should-level guidance. Requirements and permissions retain their stated scope.

## Naming

- Keep Rust's conversion and getter naming, common traits, `new` alongside `Default`, and direct capability-based feature names. — [Microsoft Pragmatic Rust Guidelines: Follow the upstream guidelines (M-UPSTREAM-GUIDELINES)](https://microsoft.github.io/rust-guidelines/guidelines/universal/index.html#M-UPSTREAM-GUIDELINES). <!-- MS:002 -->
- Recommended: Name types for their domain or operation instead of vague `Service`, `Manager`, or `Factory` labels. — [Microsoft Pragmatic Rust Guidelines: Names are free of weasel words (M-WEASEL-WORDS)](https://microsoft.github.io/rust-guidelines/guidelines/universal/index.html#M-WEASEL-WORDS). <!-- MS:014 -->
- Recommended: Call separate construction helpers builders, and represent repeated construction with an `Fn` callback instead of a factory object. — [Microsoft Pragmatic Rust Guidelines: Names are free of weasel words (M-WEASEL-WORDS)](https://microsoft.github.io/rust-guidelines/guidelines/universal/index.html#M-WEASEL-WORDS). <!-- MS:016 -->
- Recommended: Normally keep identifiers to two brief words. — [Microsoft Pragmatic Rust Guidelines: Names of items are short (M-SHORT-NAMES)](https://microsoft.github.io/rust-guidelines/guidelines/universal/index.html#M-SHORT-NAMES). <!-- MS:017 -->
- Recommended: Avoid repeating path context in names, favor understood abbreviations, and justify longer exceptions. — [Microsoft Pragmatic Rust Guidelines: Names of items are short (M-SHORT-NAMES)](https://microsoft.github.io/rust-guidelines/guidelines/universal/index.html#M-SHORT-NAMES). <!-- MS:018 -->
- Recommended: Name events in a `component.operation.state` hierarchy. — [Microsoft Pragmatic Rust Guidelines: Use structured logging with message templates (M-LOG-STRUCTURED)](https://microsoft.github.io/rust-guidelines/guidelines/universal/index.html#M-LOG-STRUCTURED). <!-- MS:024 -->
- Use the `Builder` suffix and a `builder` constructor on the built type. The helper should keep its own `new` private. — [Microsoft Pragmatic Rust Guidelines: Complex type construction has builders (M-INIT-BUILDER)](https://microsoft.github.io/rust-guidelines/guidelines/libs/ux/index.html#M-INIT-BUILDER). <!-- MS:064 -->
- Name fluent builder setters for their fields without `set_`, and name completion `build`. — [Microsoft Pragmatic Rust Guidelines: Complex type construction has builders (M-INIT-BUILDER)](https://microsoft.github.io/rust-guidelines/guidelines/libs/ux/index.html#M-INIT-BUILDER). <!-- MS:065 -->
- Recommended: Use a `sys` suffix for native API imports and an `ffi` suffix for native-callable exports. — [Microsoft Pragmatic Rust Guidelines: FFI crates follow established naming conventions (M-FFI-NAMING)](https://microsoft.github.io/rust-guidelines/guidelines/ffi/index.html#M-FFI-NAMING). <!-- MS:130 -->
