# Chromium C++ style with the Google baseline: condensed rules

Google guidance with Chromium overrides applied. Read this as one combined guide, subject to Chromium’s feature policy. Chromium initially supports C++23, with individual features still restricted.

## Quick rules

- Keep a style constraint only when its practical value justifies its learning cost. — [Google — Goals of the Style Guide](https://google.github.io/styleguide/cppguide.html#goals-of-the-style-guide). <!-- google-cpp:1 -->
- Favor code that future maintainers can read, diagnose, and change easily. — [Google — Goals of the Style Guide](https://google.github.io/styleguide/cppguide.html#goals-of-the-style-guide). <!-- google-cpp:2 -->
- Expose surprising actions at their call sites, especially changes in ownership. — [Google — Goals of the Style Guide](https://google.github.io/styleguide/cppguide.html#goals-of-the-style-guide). <!-- google-cpp:3 -->
- Stay consistent with nearby code while allowing outdated practices to be retired. — [Google — Goals of the Style Guide](https://google.github.io/styleguide/cppguide.html#goals-of-the-style-guide). <!-- google-cpp:4 -->
- Follow widely understood C++ conventions when they suit the project. — [Google — Goals of the Style Guide](https://google.github.io/styleguide/cppguide.html#goals-of-the-style-guide). <!-- google-cpp:5 -->
- Reject features whose risks or complexity outweigh their maintenance benefit. — [Google — Goals of the Style Guide](https://google.github.io/styleguide/cppguide.html#goals-of-the-style-guide). <!-- google-cpp:6 -->
