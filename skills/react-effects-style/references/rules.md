# You Might Not Need an Effect: condensed rules

A render-time state update is allowed only in the same component and behind a change check; this narrow exception does not permit other render-time side effects.

Source owner: Meta Platforms, Inc. and React documentation contributors. License: [CC-BY-4.0](../LICENSE). Changes: rules independently restated, shortened and grouped by topic; examples omitted. Unofficial; no endorsement is implied.

## Quick rules

- Derive values during rendering when possible instead of synchronizing redundant state with an Effect.
- Include every reactive Effect dependency and clean up external subscriptions and requests.

## Types and data

- Calculate information already determined by props or state instead of maintaining a second synchronized state value. — [You Might Not Need an Effect: Updating state based on props or state](https://react.dev/learn/you-might-not-need-an-effect#updating-state-based-on-props-or-state). <!-- you-might-not-need-an-effect:4 -->
- Change a component's key when its identity changes and its whole subtree should start with fresh state. — [You Might Not Need an Effect: Resetting all state when a prop changes](https://react.dev/learn/you-might-not-need-an-effect#resetting-all-state-when-a-prop-changes). <!-- you-might-not-need-an-effect:12 -->
- Hide a key-based reset in a wrapper when callers should not need to arrange it. — [You Might Not Need an Effect: Resetting all state when a prop changes](https://react.dev/learn/you-might-not-need-an-effect#resetting-all-state-when-a-prop-changes). <!-- you-might-not-need-an-effect:13 -->
- Try calculating the result or resetting with a key before retaining previous-render information. — [You Might Not Need an Effect: Adjusting some state when a prop changes](https://react.dev/learn/you-might-not-need-an-effect#adjusting-some-state-when-a-prop-changes). <!-- you-might-not-need-an-effect:14 -->
- Keep the selected item's stable identifier in state and look up the current object when rendering. — [You Might Not Need an Effect: Adjusting some state when a prop changes](https://react.dev/learn/you-might-not-need-an-effect#adjusting-some-state-when-a-prop-changes). <!-- you-might-not-need-an-effect:19 -->
- Move shared state to a common owner when that eliminates copies that must stay synchronized. — [You Might Not Need an Effect: Notifying parent components about state changes](https://react.dev/learn/you-might-not-need-an-effect#notifying-parent-components-about-state-changes). <!-- you-might-not-need-an-effect:31 -->
- Load data at the shared parent and pass it to children instead of reporting child-loaded data upward through an Effect. — [You Might Not Need an Effect: Passing data to the parent](https://react.dev/learn/you-might-not-need-an-effect#passing-data-to-the-parent). <!-- you-might-not-need-an-effect:32 -->

## Performance

- Start with a direct render-time calculation rather than assuming derived data needs a cache. — [You Might Not Need an Effect: Caching expensive calculations](https://react.dev/learn/you-might-not-need-an-effect#caching-expensive-calculations). <!-- you-might-not-need-an-effect:5 -->
- Consider `useMemo` when a costly pure calculation benefits from reuse while its inputs remain unchanged. — [You Might Not Need an Effect: Caching expensive calculations](https://react.dev/learn/you-might-not-need-an-effect#caching-expensive-calculations). <!-- you-might-not-need-an-effect:6 -->
- Declare every reactive input used by the memoized calculation in its dependency list. — [You Might Not Need an Effect: Caching expensive calculations](https://react.dev/learn/you-might-not-need-an-effect#caching-expensive-calculations). <!-- you-might-not-need-an-effect:7 -->
- Account for React Compiler's automatic memoization before adding manual caching. — [You Might Not Need an Effect: Caching expensive calculations](https://react.dev/learn/you-might-not-need-an-effect#caching-expensive-calculations). <!-- you-might-not-need-an-effect:8 -->
- Time the relevant user interaction to establish whether memoization is warranted. — [You Might Not Need an Effect: How to tell if a calculation is expensive](https://react.dev/learn/you-might-not-need-an-effect#how-to-tell-if-a-calculation-is-expensive). <!-- you-might-not-need-an-effect:9 -->
- Check whether caching reduces subsequent update time; it does not accelerate the first calculation. — [You Might Not Need an Effect: How to tell if a calculation is expensive](https://react.dev/learn/you-might-not-need-an-effect#how-to-tell-if-a-calculation-is-expensive). <!-- you-might-not-need-an-effect:10 -->
- Measure a production build under realistic device constraints, using slower hardware or CPU throttling as needed. — [You Might Not Need an Effect: How to tell if a calculation is expensive](https://react.dev/learn/you-might-not-need-an-effect#how-to-tell-if-a-calculation-is-expensive). <!-- you-might-not-need-an-effect:11 -->
- Design data loading for response reuse, server rendering, and avoidance of sequential request waterfalls. — [You Might Not Need an Effect: Fetching data](https://react.dev/learn/you-might-not-need-an-effect#fetching-data). <!-- you-might-not-need-an-effect:37 -->
- Prefer the framework's data-loading facilities when the application has them. — [You Might Not Need an Effect: Fetching data](https://react.dev/learn/you-might-not-need-an-effect#fetching-data). <!-- you-might-not-need-an-effect:38 -->
- Isolate unrelated input state in a child when doing so prevents unnecessary calculations in its parent. — [You Might Not Need an Effect: Challenges — Cache a calculation without Effects](https://react.dev/learn/you-might-not-need-an-effect#challenges). <!-- you-might-not-need-an-effect:40 -->

## Effects

- Reserve Effects for keeping React aligned with systems outside React, not for ordinary internal dataflow. — [You Might Not Need an Effect: How to remove unnecessary Effects](https://react.dev/learn/you-might-not-need-an-effect#how-to-remove-unnecessary-effects). <!-- you-might-not-need-an-effect:1 -->
- Prepare data needed for display as part of rendering itself. — [You Might Not Need an Effect: How to remove unnecessary Effects](https://react.dev/learn/you-might-not-need-an-effect#how-to-remove-unnecessary-effects). <!-- you-might-not-need-an-effect:2 -->
- Put work caused by an interaction in the handler for that interaction. — [You Might Not Need an Effect: How to remove unnecessary Effects](https://react.dev/learn/you-might-not-need-an-effect#how-to-remove-unnecessary-effects). <!-- you-might-not-need-an-effect:3 -->
- If partial state adjustment cannot be avoided, conditionally update only the rendering component's own state to avoid committing stale output. — [You Might Not Need an Effect: Adjusting some state when a prop changes](https://react.dev/learn/you-might-not-need-an-effect#adjusting-some-state-when-a-prop-changes). <!-- you-might-not-need-an-effect:15 -->
- Guard a render-time state adjustment with a meaningful change check that stops repeated retries. — [You Might Not Need an Effect: Adjusting some state when a prop changes](https://react.dev/learn/you-might-not-need-an-effect#adjusting-some-state-when-a-prop-changes). <!-- you-might-not-need-an-effect:16 -->
- While one component is rendering, never set state belonging to a different component. — [You Might Not Need an Effect: Adjusting some state when a prop changes](https://react.dev/learn/you-might-not-need-an-effect#adjusting-some-state-when-a-prop-changes). <!-- you-might-not-need-an-effect:17 -->
- The guarded state-adjustment exception does not permit DOM mutations or other unrelated side effects during render. — [You Might Not Need an Effect: Adjusting some state when a prop changes](https://react.dev/learn/you-might-not-need-an-effect#adjusting-some-state-when-a-prop-changes). <!-- you-might-not-need-an-effect:18 -->
- Factor repeated event work into a shared helper called by handlers, rather than triggering that work through an Effect. — [You Might Not Need an Effect: Sharing logic between event handlers](https://react.dev/learn/you-might-not-need-an-effect#sharing-logic-between-event-handlers). <!-- you-might-not-need-an-effect:20 -->
- Submit interaction-triggered requests from the corresponding event handler. — [You Might Not Need an Effect: Sending a POST request](https://react.dev/learn/you-might-not-need-an-effect#sending-a-post-request). <!-- you-might-not-need-an-effect:21 -->
- Use an Effect for synchronization caused by displaying the component, including display-related analytics. — [You Might Not Need an Effect: Sending a POST request](https://react.dev/learn/you-might-not-need-an-effect#sending-a-post-request). <!-- you-might-not-need-an-effect:22 -->
- Avoid cascades where each Effect updates state solely to trigger the next calculation. — [You Might Not Need an Effect: Chains of computations](https://react.dev/learn/you-might-not-need-an-effect#chains-of-computations). <!-- you-might-not-need-an-effect:23 -->
- Derive display values while rendering and perform the state changes caused by an event together. — [You Might Not Need an Effect: Chains of computations](https://react.dev/learn/you-might-not-need-an-effect#chains-of-computations). <!-- you-might-not-need-an-effect:24 -->
- Compute the intended next value explicitly when other work in the handler needs it before a new state snapshot exists. — [You Might Not Need an Effect: Chains of computations](https://react.dev/learn/you-might-not-need-an-effect#chains-of-computations). <!-- you-might-not-need-an-effect:25 -->
- An Effect chain may be justified when later synchronization depends on network results unavailable to the event handler. — [You Might Not Need an Effect: Chains of computations](https://react.dev/learn/you-might-not-need-an-effect#chains-of-computations). <!-- you-might-not-need-an-effect:26 -->
- Ensure unmounting and mounting the component again leaves its behavior correct. — [You Might Not Need an Effect: Initializing the application](https://react.dev/learn/you-might-not-need-an-effect#initializing-the-application). <!-- you-might-not-need-an-effect:27 -->
- For initialization scoped to an app load, use an app-level guard or deliberate module initialization instead of relying on a single mount. — [You Might Not Need an Effect: Initializing the application](https://react.dev/learn/you-might-not-need-an-effect#initializing-the-application). <!-- you-might-not-need-an-effect:28 -->
- Concentrate import-time application setup in entry or root modules so arbitrary component imports do not perform surprising work. — [You Might Not Need an Effect: Initializing the application](https://react.dev/learn/you-might-not-need-an-effect#initializing-the-application). <!-- you-might-not-need-an-effect:29 -->
- When an action changes both child and parent state, notify the parent and update the child in that same event. — [You Might Not Need an Effect: Notifying parent components about state changes](https://react.dev/learn/you-might-not-need-an-effect#notifying-parent-components-about-state-changes). <!-- you-might-not-need-an-effect:30 -->
- Prefer `useSyncExternalStore` for external subscriptions instead of implementing the subscription with an Effect yourself. — [You Might Not Need an Effect: Subscribing to an external store](https://react.dev/learn/you-might-not-need-an-effect#subscribing-to-an-external-store). <!-- you-might-not-need-an-effect:33 -->
- Expose reusable external-store behavior through a custom Hook with a focused purpose. — [You Might Not Need an Effect: Subscribing to an external store](https://react.dev/learn/you-might-not-need-an-effect#subscribing-to-an-external-store). <!-- you-might-not-need-an-effect:34 -->
- An Effect can keep results aligned with current query or pagination values even when those values did not originate in a particular event. — [You Might Not Need an Effect: Fetching data](https://react.dev/learn/you-might-not-need-an-effect#fetching-data). <!-- you-might-not-need-an-effect:35 -->
- Implement request cleanup so responses for superseded queries cannot replace the latest results. — [You Might Not Need an Effect: Fetching data](https://react.dev/learn/you-might-not-need-an-effect#fetching-data). <!-- you-might-not-need-an-effect:36 -->
- If fetching in Effects without a framework, consider wrapping reusable requests, loading state, and failures in a custom data Hook. — [You Might Not Need an Effect: Fetching data](https://react.dev/learn/you-might-not-need-an-effect#fetching-data). <!-- you-might-not-need-an-effect:39 -->
