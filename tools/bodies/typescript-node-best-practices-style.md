# TypeScript style: Node.js Best Practices (condensed)

Use this skill only when the user explicitly requests this source. It replaces the house `typescript-style` skill for this task.

Follow [references/rules.md](references/rules.md) when writing or reviewing TypeScript/Node.js code. Read the relevant topic sections before making changes. Each rule names and links to its original section; cite the source title and section in review findings.

This includes the Node guide's linked security and Docker checklists. Its performance chapter is draft guidance; historical runtime, browser-header, and password-rotation claims are explicitly qualified. Apply operational recommendations only within the user's authorized task.

When a rule conflicts with a formatter or linter the project already runs, the project's tooling wins. State the conflict in one line.

The bundled rules work offline. If resolving an ambiguity needs an unavailable original, state the limitation and follow the project's existing convention for that point.
